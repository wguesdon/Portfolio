## Overview

This solution combines systematic feature engineering with diverse GBDT and NN ensembles trained on AWS SageMaker. The approach follows the [KGMON Playbook](https://www.kaggle.com/competitions/playground-series-s6e3/writeups/1st-place-gpt5-4-gemini3-1-claudeopus4-6-kgm) by Chris Deotte (1st place PS6E3), adapted for this competition's unique characteristics: a deterministic original dataset with an exact generating formula, strong class imbalance (High = 3.3%), and balanced accuracy as the metric.

All training was done on AWS SageMaker spot instances configured via the AWS CLI. Code was generated with Claude Code (Opus 4.6).

## 1. Key Discovery: The Magic Formula

The original 10,000-row dataset was generated by a deterministic rule-based formula that perfectly separates all classes (BA = 1.0). Discovered by Chris Deotte in the competition discussion forum.

```python
High_score = (Soil_Moisture < 25) * 2 + (Rainfall_mm < 300) * 2 + (Temperature_C > 30) + (Wind_Speed_kmh > 10)
Low_score = (Crop_Growth_Stage == 'Harvest') * 2 + (Crop_Growth_Stage == 'Sowing') * 2 + (Mulching_Used == 'Yes')
magic_score = High_score - Low_score

# Perfect mapping on original data:
# score <= 0  -> Low
# 1-3         -> Medium
# >= 4        -> High
```

On the 630K synthetic dataset, the raw formula achieves BA = 0.961. The synthetic generator "blurred" the decision boundaries by adding continuous perturbation and label noise. Our models learn to correct for this blur.

## 2. Feature Engineering

Feature engineering is the dominant driver of performance. Our pipeline generates ~260 features across several groups.

### 2.1 Magic Score Features (15 features)

The exact formula components exposed as individual features:
- 7 boolean flags at exact thresholds (soil_dry, rain_low, temp_hot, wind_high, harvest, sowing, mulch_yes)
- 3 composite scores (high_score, low_score, magic_score)
- Boundary distance (distance to score 0 and 3 decision points)
- 4 continuous margins (how far each numeric value is from its threshold)

`magic_soil_dry` is consistently the #1 feature by importance across all models.

### 2.2 Domain Interactions (16 features)

Physics-inspired feature crosses:
- Water balance: `Rainfall_mm - Previous_Irrigation_mm`
- Heat stress: `Temperature_C * (1 - Humidity / 100)`
- Evapotranspiration: `Temperature_C * Sunlight_Hours / (Humidity + 1)`
- Drying index: `Sunlight_Hours * Wind_Speed_kmh / (Humidity + 1)`
- Moisture ratios: `Soil_Moisture / (Temperature_C + 1)`, etc.

### 2.3 Original Dataset TE Priors (19 features)

For each of the 19 base features, compute `orig.groupby(col)[target].mean()` from the 10K original dataset. Zero leakage since original data is independent of synthetic splits.

### 2.4 2-Way Interaction Target Encoding (135 columns)

All C(19,2) = 171 feature pairs filtered by uniqueness (drop pairs where nunique > N/2). The remaining 135 pairs are string-concatenated and target-encoded inside each CV fold using sklearn's `TargetEncoder(target_type='multiclass', cv=5)`.

This is the single biggest contributor to the v1-to-v2 jump (+0.009 CV).

### 2.5 Digit Extraction (22 features)

First decimal digit and 2-digit fractional part for all 11 numeric columns. Exploits artifacts from the synthetic generator's rounding behavior.

### 2.6 Frequency and Boolean Features (~30 features)

- Frequency encoding for all 8 categorical columns
- Label-encoded categoricals
- 8 hand-picked bigram cross-features with frequency encoding
- Boolean flags for domain thresholds

### 2.7 Feature-Engine Transformers (41 features)

Using the feature-engine library:
- `EqualFrequencyDiscretiser(q=10)` on all numerics (11 features)
- `EqualWidthDiscretiser(bins=15)` on all numerics (11 features)
- `DecisionTreeDiscretiser` supervised binning (11 features)
- `CountFrequencyEncoder` on categoricals (8 features)

## 3. Training Pipeline

### 3.1 Infrastructure

- AWS SageMaker for all training
- Docker images built via EC2 spot jumpbox (8 min build+push cycle)
- S3 for data and artifact storage
- SQLite ModelTracker for CV/LB score logging and diversity analysis

### 3.2 Model Training

Each model follows a 2-phase pipeline:
1. **Optuna tuning** (50 trials on 80/20 split): finds good hyperparameters
2. **5-fold StratifiedKFold CV**: trains with best params, 15K estimators, 500-round early stopping

Inside each fold:
- Original 10K data appended to training set (not validation)
- TargetEncoder fitted on train fold, applied to train/val/test
- Balanced sample weights (XGB) / is_unbalance (LGB) / auto_class_weights (CAT)

### 3.3 Diversity Strategies

Models are diversified along three axes:

**Seeds:** Each GBDT type trained with seeds 42, 43, 44, 45 producing different Optuna optima and fold splits.

**Algorithms:** XGBoost (depth-wise, GPU), LightGBM (leaf-wise, CPU), CatBoost (symmetric trees, GPU). Each has structural biases that produce different error patterns.

**Feature subsets:** Named strategies control which features each model sees:
- `all`: Full 260+ feature set
- `magic_core`: Magic score + raw numerics + encoded cats (~50 features)
- `no_interactions`: Drop 2-way TE columns
- `no_digits`: Drop digit extraction features

## 5. What We Learned

### What Worked
1. **2-way interaction TE** was the single biggest improvement (+0.009 CV from v1 to v2)
2. **Original data TE priors** provide zero-leakage signal from the original dataset
3. **Original data injection** into training folds helps the model see clean examples
4. **CatBoost** consistently outperforms XGB and LGB by ~0.006 on this dataset
5. **Threshold optimization** adds +0.002 on LB for balanced accuracy
6. **Magic score features** are the top importance features in every model

### What Did Not Work (Yet)
1. **Hill climbing ensemble** gave CatBoost 100% weight because the 3 GBDT models are too correlated. Need NN models for true diversity.
2. **Feature pruning** not yet explored. With the magic formula providing the core signal, many features may be noise.

### What We Would Do Differently
1. Start with the magic formula discovery earlier (it was found mid-competition)
2. Train NN models (RealMLP, TabM, FT-Transformer) from the start for ensemble diversity
3. Use Level 3 stacking (train models on Level 2 OOF predictions)
