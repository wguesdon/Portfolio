# PS6E4 Solution: Predicting Irrigation Need

**Competition:** Playground Series S6E4
**Task:** 3 class classification (Low, Medium, High)
**Metric:** Balanced Accuracy
**Public/Private LB split:** 20% / 80%

## Final submissions

| File | CV | Public LB |
|------|----:|----------:|
| `sub_v15_lgb_stack_log_bias.csv` (Pick 1) | 0.98045 | 0.98081 |
| `sub_v11_lgb_stack_30m.csv`      (Pick 2) | 0.98061 | 0.98072 |

Both picks are LightGBM stackers with log bias threshold tuning, run on top of a diverse pool of base models.

## Overview

The solution is a 30 to 41 model stacked ensemble. The single biggest driver was feature engineering, then model diversity, then a careful stacker over greedy choice.

The pipeline followed three principles.

1. Discover the generator. The original 10K dataset was produced by an exact rule based formula. Modeling on the 630K synthetic dataset was a regression toward that formula under noise.
2. Diversify the base pool along three axes: algorithm family, seed, feature subset.
3. Trust 5 fold CV on 630K rows over a 20% public LB. Stackers regularize themselves through their own fold structure. Greedy forward selection consistently overfit CV.

## 1. The magic formula

The 10K original dataset was generated by the following deterministic rule, originally surfaced by Chris Deotte in the discussion forum.

```python
high_score = (Soil_Moisture < 25) * 2 + (Rainfall_mm < 300) * 2 \
           + (Temperature_C > 30) + (Wind_Speed_kmh > 10)
low_score  = (Crop_Growth_Stage == 'Harvest') * 2 \
           + (Crop_Growth_Stage == 'Sowing')  * 2 \
           + (Mulching_Used == 'Yes')
magic_score = high_score - low_score

# On original data:  score <= 0 -> Low, 1..3 -> Medium, >= 4 -> High
```

On the 10K original data this maps perfectly. On the 630K synthetic dataset the raw rule scores Balanced Accuracy 0.961. The synthetic generator added continuous perturbation and label noise. Models learn to correct that residual.

`magic_soil_dry` is the single most important feature in every tree based model we trained.

## 2. Feature engineering

The pipeline produced roughly 260 features per model, organised in seven groups.

**Magic score features (15).** The 7 individual boolean flags, the 3 composite scores, distance to decision boundaries, and continuous margin to each threshold.

**Domain interactions (16).** Physics inspired crosses such as water balance, heat stress, evapotranspiration, and drying index.

**Original dataset target encodings (19).** For every base feature, the per category mean of target on the 10K original data. Zero leakage since the original is independent of synthetic train and test.

**2 way interaction target encoding (135).** All feature pairs filtered by uniqueness, string concatenated, then target encoded inside each CV fold using sklearn `TargetEncoder(target_type='multiclass', cv=5)`. This single block was the largest jump in our v1 to v2 transition (+0.009 CV).

**Digit extraction (22).** First decimal digit and 2 digit fractional part for every numeric column. The synthetic generator left rounding artefacts that carry information.

**Frequency and boolean features (~30).** Frequency encoding for all categoricals, label encoding, hand picked bigram crosses, and threshold flags.

**Feature engine transformers (41).** Equal frequency and equal width discretisers, decision tree discretiser, count frequency encoder.

A second specialised pipeline, "OTE", was adapted from `emanuellcs` and `yunsuxiaozi` (links below). It used ordered target encoding with 4x shuffle and digit extraction. The three OTE base models were our top three individual CVs.

## 3. Base model pool

The full 41 model pool spanned the following families.

| Family | Variants | Best CV |
|--------|---------:|--------:|
| LightGBM (incl. OTE, depth variants) | 8 | 0.97942 |
| XGBoost (incl. OTE, OTE+magic, shallow GPU) | 9 | 0.97938 |
| CatBoost (incl. OTE, deep, seed variants) | 9 | 0.97919 |
| RealMLP / TabM tabular nets | 3 | 0.97802 |
| ExtraTrees, RandomForest | 2 | 0.96156 |
| Logistic Regression (L1, L2, ElasticNet variants) | 4 | 0.95568 |
| KNN, GaussianNB, SVM RBF | 4 | 0.96154 |
| GBDT shallow / deep / pseudo specialised | 2 | 0.97788 |

Each model used 5 fold StratifiedKFold with seed 42. Inside each fold, the 10K original dataset was appended to the training side only, target encoders were fit on the fold train, and class weights were applied. Optuna tuned each model on an 80/20 split before the final 5 fold pass.

## 4. Ensemble strategy

We compared three stacker styles across every pool size from 22 to 43 models.

| Method | Behaviour |
|--------|-----------|
| **LGB stacker + log bias threshold tuning** | Final pick. Internally CV regularised. Tightest CV to LB gap. |
| Greedy forward selection (differential evolution weights) | Always produced the highest CV but worst LB. |
| Equal weight blend on a greedy subset | Decent baseline, no upside over the LGB stacker. |

The LGB stacker takes the OOF probabilities from each base model as features and learns a 3 class classifier on them. The log bias step then optimises a per class additive shift on the logits to maximise Balanced Accuracy on the OOF predictions. That single step adds +0.001 to +0.002 LB.

### Why stacker over greedy

The public LB is 20% of the test set. With 270K test rows, the public sample is ~54K rows, a small enough fraction that a delta of 0.0005 between two submissions is essentially noise. Greedy selection optimises CV by picking weights that exploit specific 5 fold quirks. Those quirks do not generalise. The pattern was consistent across every version.

| Method | Typical CV | Typical LB | Gap |
|--------|-----------:|-----------:|----:|
| Greedy 9 model | 0.98086 | 0.97979 | -0.00107 |
| LGB stacker 30 model | 0.98061 | 0.98072 | -0.00011 |

CV on 5 fold 630K rows is far closer to the private LB than the 20% public sample.

### Why two stackers as final picks

The Kaggle picker takes two final submissions. Both are scored on the private LB. Pairing two LGB stackers from different pool sizes hedges against pool composition risk while keeping the same internally regularised method.

- v15 maximises public LB. 41 models including the OTE waves.
- v11 has the highest CV among proven LB submissions and the tightest CV to LB gap.

## 5. What helped

1. The magic formula features. Single biggest signal.
2. Two way interaction target encoding. Largest CV jump in any single change.
3. The OTE pipeline (ordered target encoding with 4x shuffle). All three top single models came from it.
4. Adding three weak but algorithmically diverse models (ExtraTrees, Logistic Regression, KNN). Individually weak (CV 0.78 to 0.96), but the stacker learned to use them on samples where the boosting models disagreed. v11 jumped LB from 0.98042 to 0.98072 from that addition alone.
5. Log bias threshold tuning on stacker logits. Cheap and robust under Balanced Accuracy.

## 6. What did not help

1. Greedy ensemble selection at any pool size beyond 3 models. CV always rose, LB always fell.
2. Adding more weak diverse models past saturation. v17 with 43 models had +0.00012 CV over v15 but lost 0.0004 on LB.
3. Pseudo labelling without preserving the 4x OTE shuffle augmentation. CV fell from 0.977 to 0.954.
4. Hill climbing weight optimisation among only 3 GBDT models. Collapsed to 100% CatBoost weight.
5. Architecturally novel base models without proper feature handling. RealMLP on OTE features required NaN imputation that was never tuned for it.

## Methodology reference

The overall structure follows Chris Deotte's KGMON Playbook from the PS6E3 winning solution. We did not reach the 4 level stacking of that solution, but adopted its three pillars: feature engineering as primary signal, ensemble diversity along multiple axes, and CV trust over public LB.
